# app-template: a sample Cloud Run + Cloud SQL stack, cost-safe

A Cloud Run service with a Cloud SQL database, its password in Secret Manager, and a bucket mounted into the service. **It isn't part of the catalog platform**; use it only when you need a throwaway app with a database.

## What changed from Google's export

This was generated by Google's Application Design Center and used to sit at the top of `grocery-hub-channel-google-provider/`, where any `terraform apply` in that folder would have created it. The original is kept in `original-export/` as `.tf.txt` files, so Terraform can't load it.

| | Original export | This version |
|---|---|---|
| Cloud SQL edition, tier | Enterprise Plus, `db-perf-optimized-N-8` (8 vCPU, 64 GB) | Enterprise, `db-f1-micro` (shared core); only tiers up to 2 vCPU are accepted |
| Availability | Regional HA (two instances) | Single zone (`db_high_availability = true` to opt in) |
| Data cache | On | Off |
| Disk growth | Unbounded | Capped at 20 GB |
| Cloud Run | At least 1 instance always running, up to 10, plus a Prometheus sidecar | Scales to zero, at most 2, no sidecar, 1 vCPU / 512 MiB |
| Region | us-central1 | us-central1 (cheapest, see `../DEPLOYMENT_STRATEGY.md`) |
| Bucket | Default access settings | Public access prevented |
| Safety | None: `apply` would just run | Refuses to plan until `acknowledge_billable_resources = true`; every plan goes through the cost guard |
| **Monthly cost** | **≈ $1,400–1,600** | **≈ $10–15** |

Approximate list prices: the database is about $8 a month for `db-f1-micro` plus about $2 for its 10 GB SSD and backups. Cloud Run, the secret and the bucket cost cents when idle.

## Run it

```bash
cd grocery-hub-channel-google-provider/app-template
cp terraform.tfvars.example terraform.tfvars      # set acknowledge_billable_resources = true when you mean it
cd ..
STACK_DIR="$PWD/app-template" ./catalog-media/scripts/plan.sh    # plan + cost guard
STACK_DIR="$PWD/app-template" ./catalog-media/scripts/apply.sh   # cost guard again, then apply
```

`terraform.tfvars` is git-ignored, so the acknowledgement is always someone's deliberate local choice, never a committed default.

**The deployer can't run this stack yet.** `terraform-deployer` has no Cloud SQL or Secret Manager roles; this stack isn't part of the platform, and its roles weren't added. Either run it as a project owner (`USE_DEPLOYER=0`), or add `roles/cloudsql.admin` and `roles/secretmanager.admin` to the deployer in `catalog-media/scripts/bootstrap.sh`.

## Tear it down

Cloud SQL bills every hour it exists, so remove the stack when you're done. Both deletion protections are on, so it takes two steps:
1. Set `deletion_protection = false` and `deletion_protection_enabled = false` on `module "db"` in `main.tf`, then plan and apply.
2. Run `terraform destroy` in this folder, with the same `STACK_DIR` sign-in.

## Tests

`terraform test` plans the stack offline, with Google mocked, so it needs no account and costs nothing. It checks that:
- the plan is refused without the acknowledgement;
- it plans when acknowledged;
- an 8-vCPU database tier is rejected;
- Cloud Run above 10 instances is rejected.

```bash
docker run --rm -v "$PWD":/w -w /w --entrypoint sh hashicorp/terraform:1.9.8 -c "terraform init -backend=false && terraform test"
```
